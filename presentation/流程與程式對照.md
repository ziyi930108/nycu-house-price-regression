# 完整流程與程式對照

這份導讀對照本次提交模型的實際程式，供準備口頭說明與回答問題。相對連結以 GitHub 的 presentation/ 目錄為基準。表中的理由說明設計目的，並非各模組都完成獨立消融實驗的證明。

| 流程 | 實際做法與理由 | 程式／證據 |
| --- | --- | --- |
| 確認任務與資料角色 | 輸入交易屬性、輸出總價，以元的 MAE 評估。三期年度回測取自train、不混valid；最終全量fit併入valid；test無價格標籤，sample 只定義格式與編號。先釐清角色，避免將答案或範例價格當輸入。 | [正式報告第1、2節](../REPORT.md) |
| 清理資料 | 移除3列混入的英文表頭、529列train完全重複；最終併valid再移除28列跨集重複，共467,221筆。去重排除編號、包含目標價格，以免同一列重複增加訓練影響。test保留47,073筆。 | [讀檔](../research/src/prepare_data.py)、[共同清理](../research/src/model_common.py) |
| 轉換特徵 | 解析民國日期、中文樓層、地址及交易筆棟數，建立面積比例等欄位，讓原始文字表示成可學習的數值或類別。排除ID、目標、不可用的建築年月、常數管理組織、完整備註與解約情形。 | [特徵實作](../research/src/house_features.py) |
| 加入道路位置 | 既有OSM道路資料提供粗略地理描述。近期單價CatBoost使用87個基礎欄位加8個地理欄位，共95欄。各模型維度不同，道路代表點也不是精確門牌。 | [地理特徵](../research/src/round6_geo.py)、[來源聲明](../evidence/data_external/geography/ATTRIBUTION.md) |
| 建立時間回測 | 每期只用評分起點以前的train建立模型與全部價格參考，再評估其後一年。這對應利用過去成交預測較晚交易的用途。三期不是三次獨立盲測，歷史窗口曾重複參與研究。 | [年度實驗](../research/src/round79_experiment.py)、[保存結果](../evidence/outputs/round79/results.json) |
| 學習單價與總價 | 單價CatBoost的target為y/(A×10000)，面積權重A/100讓單價MAE對應總價MAE。有效面積先用正且有限的建物面積，再車位面積，否則取1。此回退只是數值縮放，並不代表真實室內面積。 | [單價及日期權重](../research/src/round79_recency_unit.py) |
| 納入時間影響 | 單價CatBoost使用365日半衰期日期權重，希望兼顧較新的市場訊息與較早資料。合法日期權重正規化，無效日期採中性1。365日是固定設定，不宣稱已證明全域最佳。 | [權重來源](../research/src/round60_recency_price_prior.py)、[單價訓練](../research/src/round79_final_unit.py) |
| 其他價格表示 | 直接總價、log總價、面積連結NN與先驗倍率NN提供不同的價格表示與函數形式。這是互補的設計動機，成效仍須看完整組合的MAE，不能說多一個模型就必然更準。 | [原訓練入口導覽](../research/README.md) |
| 避免先驗直接用自身標籤 | 價格先驗NN的訓練先驗採5折建案分組OOF：該建案訓練列使用其他折的價格資料計算先驗。query使用fit建立的狀態。建案OOF不是逐筆時間OOF。 | [先驗建立](../research/src/round60_recency_price_prior.py)、[先驗NN](../research/src/round63_recency_weighted_prior_train.py) |
| 成交參考與空間修正 | 各模型先還原成元並組成三分支，再使用fit中可比成交與趨勢。空間修正同時接收base、成交參考與支持診斷，依支持程度處理。不是直接把附近房價套給每一筆test。 | [可比成交](../research/src/round2_neighborhood.py)、[空間修正](../research/src/round8_spatial_reference.py)、[推論順序](../src/tree_runtime.py) |
| 組合三條分支 | 六模型形成單價、對數、NN三分支，其中同一LightGBM共用。逐分支修正後才逐筆取中位數，降低單一分支極端輸出的影響，但無法消除共同偏差。 | [完整推論及組合](../src/predict_v22.py)、[固定配方](../config/v22.json) |
| 最終訓練與提交 | 方法選定後，用允許的有標籤資料建立最終狀態，對test產生總價。這與保留query標籤的時間回測用途不同。原研究訓練來源保存，但本次文件製作沒有重新訓練。 | [訓練程式導覽](../research/README.md)、[模型清單](../artifacts/manifest.json) |
| 產生CSV並核對 | 按sample編號順序，最後一次np.rint取整並設最低1元，檢查有限值、兩欄名稱、47,073列、ID及順序。UTF-8 BOM與CRLF也固定，避免資料正確但交付檔格式或列序錯誤。 | [提交輸出](../src/submission_io.py)、[格式測試](../tests/test_submission_io.py) |
| 保存並重現 | 單一入口讀原test與17個保存artifact，真正重跑四個樹模型、兩個NN及各分支修正。47,073筆及CSV與原檔一致，是保存狀態推論重現，並非全新環境從零重訓證明。 | [實測範圍](../docs/REPRODUCIBILITY.md)、[成功收據](../evidence/reproduction/integration_verified.json) |

## 上台說明的用詞

可以說「這個處理希望解決什麼問題，再用完整回測確認整套方法的表現」。只有來源真的包含控制實驗與結果時，才把某個模組描述為已實證降低誤差。不要替未量測的步驟編造改善百分比。

同樣需要區分「研究時做過的訓練」、「現在保存的模型」，與「本次交付已重跑的推論」。講到84.74秒時，應明說是同機既有環境的完整推論入口耗時。

這份程式導讀與問答不計入至少12分鐘的主講；主講長度另以完整逐頁講稿估算及實際排練確認。
